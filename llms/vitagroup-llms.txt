## What this API is

The unit of work is the openEHR record. An EHR is a container for one subject; COMPOSITIONs are the clinical documents committed into it, constrained by an operational template (ADL 1.4 or ADL 2). Everything is append-only and versioned — an update creates a new version, a delete creates a version marked deleted, and any versioned object can be read at an arbitrary past instant. Reading is done with AQL, one query language over the whole record, rather than per-endpoint filters.

The important consequence: the schema is not vitagroup's. It is the openEHR Reference Model. An integrator who already speaks openEHR needs no bespoke connector.

## Authentication

Chosen by the OPERATOR at server startup, not fixed by vitagroup. `SECURITY_AUTHTYPE` is one of:

- `NONE` — the default. No credentials. This is what the public sandbox runs.
- `BASIC` — HTTP Basic against a configured user/password and admin user/password.
- `OAUTH` — OAuth 2.0 resource server. Validates a bearer JWT against an operator-configured issuer (Keycloak in HIP) and reads the role from `realm_access.roles` or `scope`. Two levels only: user (default role name `USER`) and admin (default `ADMIN`), both renameable.

The three open-source OpenAPI documents declare NO securitySchemes, so a generated client will not expect an auth failure. Only the enterprise spec declares `bearerAuth`.

## Runtime semantics an agent must know

- **Concurrency**: `If-Match` carrying the `version_uid` is required on `updateComposition`, `updateEhrStatus`, `updateDirectory` and `deleteComposition`. A stale value returns 412 with the current `version_uid` in `ETag`. Re-read and re-apply; never strip the header.
- **Audit**: send `openEHR-AUDIT_DETAILS` on writes. It is persisted with the CONTRIBUTION.
- **Representation**: `Prefer: return=representation` or `return=minimal`.
- **Point in time**: `version_at_time` on versioned reads. A 404 there may mean "nothing at that instant", not "does not exist".
- **Paging**: `offset` and `fetch` on AQL. No cursor, no total count.
- **Idempotency**: NOT supported. No `Idempotency-Key`. `POST .../ehr` and `POST .../composition` are not idempotent. `PUT /rest/openehr/v1/ehr/{ehr_id}` (createEhrWithId) lets you choose the id and is the retry-safe way to create.
- **Errors**: no RFC 9457. Branch on the status code. 400 invalid content, 401 credentials, 403 admin role missing, 404 not found, 409 EHR already exists for that subject, 412 stale If-Match, 422 template still in use, 501 contribution delete withdrawn since 2.0.0.
- **Rate limits**: none published, none observed. No `X-RateLimit-*`, no `Retry-After`, no 429 declared anywhere.
- **Dry run**: not supported.

## Reversibility

- Composition delete is LOGICAL — prior versions stay readable. Recoverable.
- Contribution `rollback` (enterprise only) reverses a whole contribution using the Saga pattern. Documented, but NO time window is stated.
- Every `/rest/admin/**` delete is PHYSICAL and irreversible.
- `mergeEhrs` has no unmerge. vitagroup's own docs: "Even if unmerging data is stored for each merge, the unmerge operation is not possible at the moment."

Do not call an admin delete or a merge without explicit human confirmation.

## Events

HIP EHRbase enterprise ships Event Trigger: an operator registers a rule whose condition is an AQL query and whose action forwards the projection over HTTP, AMQP/RabbitMQ, Kafka or a log sink, firing BEFORE or AFTER a COMPOSITION or EHR_STATUS create/update/delete. There are no vendor-defined event types — the operator defines them. No AsyncAPI document is published, no delivery guarantee is documented, and payloads are not signed.

## Standards

openEHR ITS-REST (primary), openEHR Reference Model, AQL, ADL 1.4 / ADL 2, IHE ATNA audit logging (enterprise), OAuth 2.0, HTTP conditional requests (ETag / If-Match). HL7 FHIR and HL7v2 are supported through separate bridge components (FHIR Bridge, openFHIR, FHIRconnect) rather than as a native FHIR server — no FHIR CapabilityStatement is published.

Not implemented: RFC 9457 problem details, RFC 8594 Sunset headers, Idempotency-Key, AsyncAPI, SCIM.
